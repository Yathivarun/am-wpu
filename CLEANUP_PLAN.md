## 5. Setup & release scripts (req #5)

### 5.1 Model bundling decision — **RECOMMENDATION: bundle inside the release zip**
**Reasoning:**
- **Size is a non-issue.** The bundled models are `mobilefacenet.onnx` (8.0 MB) +
  `face_recognition_sface_2021dec.onnx` (37 MB, kept for v1) +
  `face_detection_yunet_2023mar.onnx` (0.23 MB) ≈ **45 MB** — trivially bundleable. The
  removed 249 MB + 63 MB legacy models were the only reason the tree looked heavy.
- **Offline reliability:** the Pi is a kiosk that must survive with no/flaky network
  (that's the whole point of diagnostic mode). A URL fetch at setup adds a hard network
  dependency and a failure mode on first boot. Bundling removes it.
- **Version consistency:** the release is a *version-locked zip*. Bundling the model
  guarantees code and weights always match — a URL can drift, 404, or serve a newer
  incompatible model. The embedding pipeline is exactly matched to *this* model's
  preprocessing, so a mismatch silently corrupts recognition.
- **Verdict:** bundle. Reserve URL-fetch only if a future model exceeds a few hundred
  MB; then host a versioned, checksummed artifact and pin the URL+SHA256 per release.

## 6. Slideshow stock-image filename bug (req #6)

**Root cause** — `slideshow_service.py:488-495` (`_load_stock_images`), triggered by the
default `sort_mode: "numeric"` (`config.yaml:20`, `settings.py:24`). The sort key returns
`int(name)` for digit-named files but the `str` basename otherwise:

```python
key=lambda p: (int(...) if ....isdigit() else os.path.basename(p))
```

When the directory mixes numeric (`1.png`) and non-numeric (`varun.png`) names, Python 3
compares an `int` against a `str` during sort → **`TypeError: '<' not supported between
instances of 'int' and 'str''`** → the slideshow crashes. (It works *today* only because
every file happens to be `1.png`…`16.png`.) Loading itself already filters by extension
via `glob`, so no extra filtering is needed — only the sort key is unsafe.

**Fix (CODE FIX):** make the sort key type-consistent so any filenames load, in a natural
order, with no naming requirement:

```python
def _natural_key(path):
    name = os.path.splitext(os.path.basename(path))[0]
    # (0, number) sorts numeric names first & numerically; (1, name) sorts the rest.
    return (0, int(name)) if name.isdigit() else (1, name.lower())
...
image_files.sort(key=_natural_key)   # replaces the numeric/alphabetical branch
```
Also apply the same robustness to `_load_person_sketches` (`:520-532`) if it ever sorts.
Recommend changing the default `sort_mode` to `"alphabetical"` (or dropping the option)
so a mixed folder never hits the fragile path. Same one-line class of bug does **not**
affect `glob` filtering — valid extensions already come from `config.image_extensions`.

`Conflicts=` guarantees that `systemctl start` of one **stops the other first**, so they
never fight for the camera/display. `scripts/switch-mode.sh` makes it a one-liner:
```bash
#!/usr/bin/env bash
set -euo pipefail
case "${1:-}" in
  server)     sudo systemctl start slideshow-server.service ;;      # Conflicts= stops diagnostic
  diagnostic) sudo systemctl start slideshow-diagnostic.service ;;  # Conflicts= stops server
  *) echo "usage: switch-mode.sh {server|diagnostic}"; exit 1 ;;
esac
systemctl is-active slideshow-server.service slideshow-diagnostic.service || true
```
`setup.sh` step [6-7]: copy both units → `daemon-reload` → `enable server` → leave
`diagnostic` disabled-but-present.
