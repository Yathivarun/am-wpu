# Codebase Summary — wpu-client

Generated by scanning the repository on 2026-07-10. This is a **read-only summary** —
nothing was deleted or modified while producing it.

`wpu-client` is a Raspberry Pi kiosk app: a GTK4 fullscreen slideshow + an
OpenCV/onnxruntime face-recognition service that talks to a remote "WPU" server
(or, in diagnostic mode, a local seeded gallery) to identify visitors and swap the
slideshow to that visitor's personalised images.

## 5. Dynamic imports, reflection, and string-based file references

No `importlib`, `__import__`, plugin registries, or reflection-based class loading were found anywhere in the codebase — all Python imports are static `import`/`from...import` statements. However, several **runtime, string-built file paths** exist that a naive "grep for the filename" search would miss:

- **ONNX model paths built from `__file__`**: both `face_service.py` and `sface_embedder.py` construct model paths as `os.path.join(os.path.dirname(os.path.abspath(__file__)), "<model>.onnx")` rather than importing the model — so the `.onnx` files under `wpu_client/services/face_recognition/` are "used" only via these string joins, not via any import statement. (This is exactly why `exp3_freeze90_arcface.onnx` and `glintr100_int8_static_150.onnx` stand out: nothing builds a path containing those filenames anywhere.)
- **Dataset directory path**: `face_service.py` computes `DATASET_DIR` the same way (three `os.path.dirname` calls up from the file's own location) rather than an absolute/config-driven path.
- **Glob-based image loading**: `SlideshowApp._load_stock_images()` and `_load_person_sketches()` (`slideshow_service.py`) load images via `glob.glob(os.path.join(dir, ext))` over `config.yaml`'s `image_extensions` list — so individual files under `stock_images/` and `diagnostic_gallery/<slug>/sketches/` are never referenced by name in code; they're discovered purely by directory + extension pattern at runtime.
- **Diagnostic gallery loading**: `DiagnosticGallery.load()` (`diagnostic_gallery.py`) enumerates `diagnostic_gallery/*/` subdirectories with `os.listdir()`, then looks for `embedding_*.npy`/`meta.json`/`sketches/` by fixed naming convention — again, no static reference to any specific person's files.
- **Config-driven directories**: `image_directory`, `diagnostic_gallery_dir` in `config.yaml`/`settings.py` are plain strings resolved at runtime — changing `config.yaml` silently repoints which directory's contents are "used" without any code change.
- **Dataset per-person folders**: `_save_dataset_frame()` sanitizes the recognized person's name into a folder name and creates it on demand (`dataset/<safe_name>/`) — so `dataset/`'s subfolder structure is entirely a runtime side-effect, not something declared anywhere in code.
